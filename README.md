# 元素モンスターズ図鑑

## 1. サービス概要

元素をモチーフにしたモンスター等のイラストを投稿・閲覧できる、元素学習SNSサービス。<br>
元素名・元素記号とイメージ画像を関連付けることで、楽しみながら元素を覚えられる学習体験を提供する。また、クリエイターが元素をテーマにした作品を発表・共有できる場としても活用できる。

### キャッチコピー

見つけよう、推し元素。<br>
「覚える」から「好きになる」へ。あなたの一枚が、未来の科学者を生み出す。

---

## 2. このアイデアはどこから生まれたか

学生時代、元素記号を勉強したとき「20個程度でも暗記するのは大変」という記憶が今でも残っている。一方で、子どもの頃に夢中になっていたポケモンは、151匹もの名前や特徴を自然と覚えていた。この経験から「もし元素もポケモンのように、それぞれが個性的なモンスターとして表現されていたら、もっと楽しく学べるのではないか」と考えるようになった。

また、私は画集やSNS等でイラストを見ることが好きで、多くのクリエイターの発想力や表現力にいつも驚かされている。さらに近年は生成AIの普及により、イラストを描けない人でもアイデアを形にしやすい時代になった。例えば「H(水素)だから水属性の魔法使い」「Au(金)だから金の鎧を着た英雄騎士」といった発想を作品として共有できれば、元素を覚えるきっかけにもなるのではないかと感じた。

この考えについて調べる中で、認知心理学では「絵優位性効果(*1)」や「二重符号化理論(*2)」があり、文字情報と視覚情報を組み合わせることで記憶の定着を助けることが示されていることを知った。

クリエイターの小さなアイデアが、子どもたちや学習者の「覚えやすい」「楽しい」を生み出し、その積み重ねが未来の科学者を育てるきっかけになるかもしれない。そんな「学び」と「創作」がつながる場所があったら面白いと思い、このサービスを考えるようになった。

元素をテーマにしたキャラクター作品はいくつか存在するものの、クリエイターが自分でデザインした元素キャラクターを投稿・共有したり、利用者がお気に入りの作品を図鑑のようにコレクションしたりできるサービスは見つからなかった。そのため、「無ければ自分で作ろう」と考え、このサービスの開発を決めた。

#### 参考文献
  - *1：Standing, L. (1973). Learning 10,000 Pictures.
  - *2：Paivio, A. (1971). Imagery and Verbal Processes.

## 3. 課題の整理

#### 学習者

- 元素は暗記学習になりやすく、興味を持ちにくい
- 記号と名前だけだと、覚えるのが難しい
- イメージで覚えられる教材が少ない

#### クリエイター

- 投稿先は多いが、作品が誰かの役になっている実感を得にくい
- 創作は自由が故にテーマを絞り辛く、アイディアを形にするまで時間がかかる
- 一度投稿したら終わりになりやすく、時間がたつと埋もれてしまう


### 本当に解決したい課題は？

元素は学ぶもの、イラストは創作するものとして、それぞれ独立している。
学びと創作をつなぎ、互いに価値を生み出せる場が少ない。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

#### 学習者

SNSでイラストを見ることが好きな中学生から大学生を想定。学校で化学（元素）を学ぶ年代であり、イラストやアニメ、ゲーム、漫画などのキャラクターコンテンツに親しんでいる層。暗記だけでは元素を覚えにくいと感じており、楽しみながら学べる方法を求めている。

#### クリエイター

SNSへイラストを投稿している、または投稿したいと考えているクリエイターを想定。創作意欲はあるものの、「何を描けばよいか」というテーマ選びに悩むことがあり、自分の作品が誰かの役に立つ形で長く活用される場を求めている。

### 4-2. 実際に使われる可能性について

サービスを最初に利用してくれるのは、元素が好きな人や理科に興味のある学生、そして新しい創作テーマを探しているイラスト投稿者だと考えている。学習者はテスト勉強や元素について調べる場面でこのサービスを思い出し、クリエイターは新しい作品のテーマを考える際や創作のアイデアに悩んだときに利用することを想定している。

現在、学習者は教科書や参考書のみで学習することが多いと思われる。イラストを探すとしても、Google画像検索やPinterest、Pixivなどを利用することが多いと思われる。一方で、それらは学習とイラストとの繋がりが薄く、元素を楽しく学ぶことや、創作活動を支援することを目的としたサービスではない。

本サービスでは、元素ごとにイラストと学習情報をまとめて閲覧できるだけでなく、クリエイターにとっても「元素」という明確な創作テーマを提供できる。また、一度投稿した作品が元素ごとのページに蓄積されることで、新着投稿として消費されるだけでなく、学習コンテンツの一部として継続的に閲覧される可能性がある。この点が既存サービスとの違いであり、利用してもらえる理由になると考えている。

### 4-3. ユーザーがサービスを導入して利用するまでのイメージ

- サービスを知る・思い出すきっかけ

  学習者はSNSで流れてきた元素モンスターのイラストや、学校で元素を学ぶタイミングをきっかけにサービスを知ることを想定（本サービスからイラスト付きでSNS共有できる機能を付ける）。また、クリエイターはSNSで投稿された作品やハッシュタグ、他のクリエイターの紹介などを通じてサービスを知り、「元素をテーマにした創作コミュニティ」という特徴に興味を持つことを期待している。

- 最初の一歩

  学習者は気になる元素を検索したり、イラストを眺めたりしながら、それぞれの元素の特徴を知るところから利用を始める。その後、お気に入りの作品を保存したり、関連する元素を見比べたりすることで、自然と学習へつながっていく。

  クリエイターはまず他の投稿作品を閲覧し、元素ごとにさまざまな表現があることを知る。その中で「自分ならこの元素をどう表現するだろう」と発想を膨らませ、作品を投稿することを最初の行動として想定している。

- 利用を続ける理由

  学習者は、新しいイラストやモンスターを見る楽しさを通じて、繰り返し元素に触れる機会が生まれ、学習を継続しやすくなる。また、同じ元素でも異なる表現を見ることで理解が深まり、学ぶ楽しさを感じられる。

  クリエイターは、作品が元素ごとのページに蓄積され、長期的に閲覧されることで、自分の創作が学習者の理解や興味につながっていることを実感できる。さらに、他のクリエイターの表現から刺激を受け、新たな創作意欲が生まれることで、継続的な投稿につながることを期待している。

### 5-2. それでも自分が作りたい理由

既存のイラスト投稿サービスは作品を投稿・閲覧することが主な目的であり、学習へつながる仕組みはほとんど用意されていない。一方で、元素をキャラクター化した書籍やゲームは存在するものの、制作者が作成したキャラクターをユーザーが楽しむ一方向のコンテンツが中心であり、ユーザー自身が創作に参加できる場は少ない。

本サービスでは、クリエイターであれば誰でも元素をテーマにしたキャラクターやモンスターを投稿できる。投稿された作品は学習者が閲覧し、元素への興味を持つきっかけとなるだけでなく、イラストを活用した学習ゲームやクイズにも発展させる予定である。また、クリエイターは自身のSNSアカウントへの導線を設けることで、作品発表だけでなく認知拡大の場としても活用できる。

「学ぶ人」と「創る人」が互いに価値を提供し合い、創作と学習が循環するコミュニティを実現したいと考えている。

### 5-3. 差別化ポイント

- 元素ごとに専用ページを用意し、イラスト・基本情報・特徴を一つの場所に集約する。
- イラスト投稿と元素学習を組み合わせたサービスであり、閲覧だけでなく学習にも活用できる。
- イラストを活用した学習ゲーム（例：イラストと元素記号から元素名を当てるクイズなど）を実装し、ゲーム感覚で元素を学べる仕組みを提供する。
- お気に入り登録機能により、自分だけの「推し元素モンスターズ図鑑」を作成できる。
- 投稿数が増えた後は、人気投票やランキング機能を導入し、元素ごとの人気モンスターを楽しめるコミュニティへ発展させる。
- クリエイターは自身のSNSアカウントを掲載できるため、作品発表だけでなく自身の活動の認知拡大にもつなげられる。
- ユーザー参加型のサービスであるため、多様な発想やデザインが集まり、学習者は一つの元素に対してさまざまな表現に触れることができる。

## 6. このサービスで提供したい価値

### 学習者に提供する価値

- 楽しみながら元素や化学の知識を身につけられる。
- イラストと元素名・元素記号を結び付けることで、知識が記憶に定着しやすくなる。
- ゲーム感覚で繰り返し元素に触れられるため、学習を継続しやすい。
- 一つの元素に対するさまざまな表現に触れることで、理解が深まる。
- 「もっと知りたい」「もっと覚えたい」という知的好奇心を育める。
- 元素を「覚えるもの」から「好きなもの」へと変える学習体験を提供する。

### クリエイターに提供する価値

- 「元素」という明確なテーマがあることで、創作のアイデアを生み出しやすい。
- 自分の作品が学習者の理解や興味につながることで、人の役に立っている実感を得られる。
- 投稿した作品が学習コンテンツとして活用されることで、作品が長く価値を持ち続ける。
- 元素ごとのページに作品が蓄積されることで、一度きりではなく継続的に閲覧される機会が生まれる。
- 自身のSNSや活動への導線を通じて、認知拡大や新たなファンとの出会いにつなげられる。
- 他のクリエイターの作品から刺激を受け、新たな創作意欲や表現の幅を広げられる。


### 6-2. 本質的な価値

学ぶ人と創る人が、それぞれの活動を通じて互いに価値を生み出し合えるコミュニティを提供する。<br>
創作が学びを支え、学びが新たな創作を生み出す循環をつくることで、「覚える」だけでは終わらない、知的好奇心と創作意欲が育ち続ける場を実現する。

## 8. このアプリの懸念点とその対策

###  懸念① 投稿が集まらない

  - 理由：ユーザー投稿型サービスのため、投稿が少ないと「学習と創作が循環するコミュニティ」として十分に機能しない可能性がある。

  - 対策：
    - サービス開始時に初期コンテンツ（元素イラスト）を用意する。
    - 自身でも継続的に作品を投稿する。
    - SNSで投稿者を募集し、サービスの認知拡大を図る。
    - イラストを描く知人やコミュニティへ協力を依頼する。

### 懸念② 不適切な画像が投稿される可能性がある

  - 理由：ユーザーが自由に投稿できるため、不適切な作品や権利侵害となる作品が投稿される可能性がある。

  - 対策：
    - 利用規約で禁止事項（暴力的・性的・権利侵害など）を明確に定める。
    - 管理画面を実装し、不適切な投稿は確認・削除できるようにする。
    - 運営が不適切と判断した投稿は削除・非公開とする。
    - （将来的には）ユーザーからの通報機能を実装する。

### 懸念③ 著作権・AI画像への対応

- 理由：手描き作品だけでなくAI生成作品の投稿も想定しているため、著作権侵害や無断転載などのトラブルが発生する可能性がある。

- 対策：
  - 投稿時に「手描き」「AI生成」を選択できるようにする。
  - 投稿者本人が権利を有する作品のみ投稿可能とし、権利侵害や無断転載は禁止する。
  - 不適切な投稿は運営の判断で削除・非公開とする。

## 9. 今後の展開・発展の方向性

### 1. 学習体験の拡張・進化

イラストを眺めるだけでも楽しめるサービスを目指しつつ、学習を継続したくなる仕組みを追加していく。

- 元素記号クイズ
- 学習履歴の可視化
- 正答率・苦手元素の分析
- レベルアップ・バッジ獲得
- 科学コラムや豆知識
- 元素ごとの詳しい解説

### 2. クリエイターが活躍できる場所へ

イラストを投稿するだけで終わらず、作品が評価され、多くの人の学習に役立つ仕組みを目指す。

- いいね
- コメント
- フォロー
- 人気ランキング
- ピックアップ作品
- 月間・年間表彰
- 学習に利用された回数
- 図鑑登録数
- お気に入り登録数

これらを通じて、「誰かの学びに貢献できた」という実感を得られるようにする。

また、作品やクリエイタープロフィールからSNS・作品投稿サイトへアクセスできる導線を設け、認知拡大や新規ファン獲得につなげる。さらに、人気作品や注目クリエイターを定期的にトップページや特集記事で紹介し、新たな作品との出会いを生み出す。

### 3. コミュニティとして成長

投稿作品が増えるほど、ユーザー同士が楽しめるイベントを開催できる。

- 推し元素総選挙
- 人気モンスターランキング
- テーマ別イラストコンテスト
- 季節イベント
- 元素の日キャンペーン

### 4. オンラインからリアルへ

サービス内だけではなく、作品をリアルな形でも楽しめるようにする。クリエイターにとっても、作品発表の場を広げられる可能性がある。

- 電子画集
- 書籍化
- イラスト作品集
- 展示会
- ポップアップイベント
- グッズ販売

### 5. 他分野への展開

元素というテーマで培った「イラストで楽しく覚える」という仕組みを、他分野にも展開できる。「暗記」を「好き」に変えるプラットフォームへ発展させることを目指す。

- 歴史モンスターズ図鑑
- 地理モンスターズ図鑑
- 世界遺産モンスターズ図鑑
- 国名モンスターズ図鑑
- 偉人モンスターズ図鑑
- 生物モンスターズ図鑑
- 宇宙モンスターズ図鑑

## 10. 技術スタック

### 10-1. 使用予定の技術

- 言語 / フレームワーク：Ruby 3.4系 / Ruby on Rails 8系
- DB：PostgreSQL 18系
- デプロイ先：Render + Neon
- 画像アップロード：cloudinary
- 環境構築：Docker
- バージョン管理：Git/GitHub

### 10-2. 技術選定の理由

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby / Ruby on Rails | 採用 | Railsガイドをはじめとした日本語の情報が豊富で、既に学習経験があるため、学習コストを抑えながら開発を進められる。<br>また、「設定より規約」の思想により設定で迷う時間が少なく、CRUDや認証機能などの標準機能を活用して、アプリの機能開発に集中できると考え採用した。 |
| PHP / Laravel | 不採用 | Webアプリ開発に適したフレームワークだが、Laravelの学習経験がなく、新たな学習コストが発生する。既に学習を進めているRailsの方が効率よく開発できるため、不採用とした。 |
| PostgreSQL | 採用 | 本番環境で利用するNeonがPostgreSQL専用のサービスであるため採用した。RailsはPostgreSQLとの相性が良く、大規模サービスでの採用実績も豊富で信頼性が高い。 |
| MySQL | 不採用 | 代表的なRDBだが、Neonを利用する本構成ではPostgreSQL一択となるため不採用とした。 |
| Render / Neon | 採用 | どちらも無料枠があり初期コストを抑えられる。GitHubへのpushで自動デプロイされ、NeonとRenderは接続文字列の設定のみで連携できるため、構築・運用が容易である。 |
| AWS | 不採用 | 自由度が高く、本番環境で広く利用されている。しかし、多種なサービス構成やネットワーク等、学習すべき内容が多く、学習コストが高い。今回のWebアプリにはオーバースペックと判断し、不採用とした。 |
| Cloudinary | 採用 | 無料枠が充実しており、初期の運用コストを抑えられる。また、RailsのActive Storageと簡単に連携でき、少ない設定で画像アップロード機能を実装できることから採用した。 |
| Cloudflare R2 | 不採用 | 保存機能は十分だが、画像加工機能が標準でなく実装工数が増えるため不採用とした |
